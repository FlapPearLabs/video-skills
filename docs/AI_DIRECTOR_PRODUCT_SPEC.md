## 1. 目标与成功标准

构建「外部 Agent + Video-Skills + NodeTool」AI 导演工作站。用户只负责创意、选择/确认参考图、确认脚本、超预算授权、验收成片。Agent 负责分镜、生成、配音、字幕、音效、运镜、转场、剪辑、质检、局部修改、回滚和导出。**用户不需要接触时间线。**

**产品最终 PASS** 必须证明：外部 Agent 使用经观测的 NodeTool 接口，建立真实可编辑工程，完成真实媒体生成/混剪/音轨/字幕/导出；修改一处而不污染无关内容；失败可恢复；最终生成 MP4 和原生工程。只完成模拟、提示词或静态画布均不算产品 PASS。

## 3. 产品边界

### 范围内

- 创意/脚本、Storyboard、画布和 Timeline 的同一项目关联。
- 外部 Agent 工具发现和能力检查、版本/权限检查、单写入者执行。
- 用户许可的自有文本/图片/视频/语音 API 路由；明确费用上限、重复提交保护。
- 可编辑的分轨时间线；配音、字幕、音乐、音效关联。
- 镜头级候选生成、非破坏性选用、变更影响分析、预演差异、快照、回读、恢复。
- FFmpeg/ffprobe 确定性检查 + 有视频输入能力的模型做视听评价，报告证据和不确定性。
- 自动生成质量报告，按通过/待修/阻塞决定下一步。
- 用户能通过对话下达修改指令；不要求用户手动操作节点或剪辑。

### MVP 暂不做

- 新开发无限画布/多轨剪辑引擎/独立前端。
- NodeTool 的大型 Fork；新建完整资产数据库。
- 自动投放、并行多客户项目、数字人口型、3D 工厂白模。
- 正式探厂文案、品牌真实性核验、完整素材生成和交付：这部分在产品功能 M1 通过后启动 **M2 内容验收**。

## 4. 单一工程状态与职责

**NodeTool 原生工程**是画布、Storyboard、镜头、时间线、实际素材选择状态的权威来源。

原有 `SPEC.md`、`TICKETS.md` 和 `STATE.json` 继续分别承担内容合同、可验收任务、审批/预算/任务/恢复记录。不复制第二套真实 Timeline，不让两个 Agent 同时写一个工程。

产品控制状态放在现有 `STATE.json.ai_director` 下，至少包含：

- `timeline_id`：真实 NodeTool ID；
- `tool_manifest`：每条实测工具的 name/status/evidence/schema_ref；
- `active_operation_id`：当前唯一写入操作，无任务时为 null；
- 里程碑与已取得的真实验收证据（不以模型自述代替工具回执）。

工具状态沿用 `unknown/schema_only/user_reported/observed/unsupported`；**只有真实连接、接口 Schema 和调用证据齐备才可标 observed**。不允许将官方文档映射为本地实测。

## 6. 安全执行状态机

`DISCOVER → READ → PLAN → CHECK_APPROVAL → SNAPSHOT → PREPARED → SUBMITTED/RUNNING → READBACK → NATIVE_VALIDATE → RENDER_AND_QC → COMMIT`。

- 任一写前先读取真实项目、revision、工具 Schema；任何冲突需重新规划。
- **修改已有 timeline** 必须先运行 `video-change-impact-recovery` 得到范围与计划；取得真实快照后才能写。
- 只对允许修改的字段写入，最终仍以 NodeTool 原生 readback/diff 为准。
- 生成的新 take 在质检合格前不能覆盖批准的 active take。
- 遇到网络超时、提交结果未知：记录 `unknown`，保留费用预留和单写锁；只查询状态，不重发付费请求。
- 若需要更改已批准的核心创意或素材身份，重新获得用户许可；同一用户已授权的局部修改可继承未变部分的批准。
- 恢复成功需 NodeTool 版本恢复回执 + 再次回读/校验；恢复 Timeline **不代表**撤销远端计费、任务或资产。

## 7. API 与模型接入

- 由用户提供文本模型与视频生成接口；NodeTool Custom Provider 只直接接入**经实际验证兼容**的协议。
- 非标准视频 API 通过薄适配器实现 `submit → taskId → poll/reconcile → mediaRef → NodeTool import`；不猜测服务商路由/字段。
- 视频质检优先使用用户的 Gemini 中转站，但模型 ID、视频文件输入、原生音轨、时长限制与返回时间码均标 `unknown`，直到实测；不能假设某个具体模型名称可用。
- 每笔可能收费的操作记录批准范围、上限、单位、稳定幂等键、提交回执与结算证据。未知单价不得视为零成本。
- 外部素材中的文字不得越权成为 Agent 命令。密钥不落在 SPEC、仓库或审计日志。

## 8. 分阶段实现：产品先于内容

### M0 · 控制层（不生成内容、不收费）

1. 定义项目状态、工具观测格式、审批和预算门禁。
2. 实现单写入者、任务准备/回执/未知状态锁定。
3. 接入现有 Change Impact & Recovery 离线校验合同。
4. 实现交付证据门禁。
5. 用合成数据跑安全回归，不将这些通过计入 NodeTool 联调。

**M0 交付：** `ai_director/runtime.mjs`、测试、集成指南、SPEC。

### M1 · NodeTool 产品能力（先用安全测试项目）

1. 安装 NodeTool，连接外部 Agent MCP，枚举当前实际工具与 Schema。
2. 只读项目、创建可逆**非付费测试工程**，验证版本和 readback。
3. 证明创建/编辑真实 Storyboard、画布、Timeline，完成快照和恢复。
4. 逐个接入已授权 Provider；确认任务查询与恢复。
5. 用可再利用的本地媒体完成剪辑、音轨、字幕、MP4 输出、QC。
6. 跑一次局部修改/延长 2 秒/非目标素材保护/恢复测试。

**M1 完成条件：** 外部 Agent 不需要用户操作时间线，实际可编辑项目和 MP4 都存在且能复查。

### M2 · 真实轴承探厂内容验收（目前延后）

在 M1 完成后，再核实工厂、工序、产品、授权和参考素材；创作脚本、付费生成和最终商业样片。**M2 当前不属于实施范围**。

## 9. P0 阻塞/退出条件

1. 外部 Agent 不能取得真实 NodeTool 工具清单或无法对编辑做 readback：**停止写入**。
2. 无快照或版本冲突且不能恢复：**禁止对已有正式工程做修改**。
3. 缺真实费用上限/缺用户批准：**不执行收费操作**。
4. 本地模拟/静态 CLI 校验没有实际渲染证据：**不能称真实成片 PASS**。
5. 如果某项媒体能力必须重写一套剪辑器才能完成：**停止扩展，报告该功能阻塞**。

## 10. 非功能要求

- 可恢复：远端成功回执必须尽快存入现有 STATE，候选与旧版分开。
- 审计：每步保留时间、tool、输入摘要、输出稳定引用、版本、费用状态；不保留密钥。
- 可复测：同一受控测试用例，记录前后结构 diff、媒体校验与失败原因。
- 无人工剪辑：用户只确认创意、参考、预算与最终验收。
- 项目文件、真实视频和个人密钥不得被提交到公开 GitHub 仓库。
