# 视频创意讨论

读 [项目约定](references/project-contract.md)、当前 [预设](references/profiles.md)；拆片和预演时读 [质量规则](references/quality.md)。先读取已有选择，避免重复询问。

## 执行

1. 整理已知与未知：给谁看、希望观众做什么、成片长度/平台、真实卖点、素材、预算、必须保留和禁止出现的内容。事实能从资料找到就先查；重要创意决定由用户做。
2. 真实打开上传图片/视频。参考视频按时间码列 `段落/Hook/画面/声音/A或B-roll/作用/可替换区间/替换素材/替换后效果`。缺素材时标待看；不可写“已拆解”。现有 annotate-video-language 等技能能用时复用，缺失时用已有播放器与抽帧工具，不强制安装。
3. 构建决定依赖：观众与目的 → 创意方向 → 人物/场景 → 分镜/节奏。每轮只问当前能决定的 1–3 个问题，给 2–3 个有明确差异的选项和推荐理由；回答后再展开依赖问题。
4. 做可比较的视觉选择。优先真实素材裁切、现成参考帧或文字分镜。使用生图候选时先确认现有预算是否覆盖；提示词/占位图不是已生成预览。候选固定同一产品与构图基线，仅改变本轮选择变量；编号 A/B/C，逐项标来源与待解决问题。
5. 用户选定后，把 exact 引用、选择理由、人物/产品必须保持的特征、场景固定点、否决方向保存到 SPEC 的创意区与 STATE.assets。Agent 的 selected 和用户 approved 分开记录。
6. 需要确认节奏时，用已有静帧与声音排出简易动态预演；文字卡或空占位明确标注。需要模型生成的动作样片仍受预算门禁。没有播放器/合成能力就输出带时长的分镜板并标 animatic 未验证。
7. 展示“已定/未定/下一步”。重要分支尚未决定时继续讨论；已清楚时展示最终方向供确认，再交 `video-to-spec`。用户已明确选定完整方向时不重复 Grill。

## 交付

把讨论写进 SPEC 草稿，不新建独立聊天数据库。至少保留一个可说明的创意：Hook → 核心画面变化/证据 → 结尾；能指出每段为什么存在。
不要用“高级、震撼、有科技感”替代构图、动作、节奏和声音描述。

## 失败分支

| 触发 | 第一处理 | 仍失败 |
| --- | --- | --- |
| 用户“没想法” | 用真实素材给 2–3 个小而具体的方向 | 先选最易验证的 5–10 秒段落，不替其决定品牌故事 |
| 参考有风格但本地素材不足 | 标出可复用节奏与不能照搬的画面 | 把缺口写入后续素材 Ticket |
| 关键方向互相冲突 | 展示两种短分镜及取舍 | 只问会改变生成结果的那一个问题 |
| 无生图/预算 | 展示真实帧或文字分镜并说明来源 | 不冒充多模态预览已交付 |

## 禁止

不要自动把参考视频故事照搬成新广告；不要发明优惠、产能、认证或用户反馈；不要在用户选择前提交收费候选或视频。
不要要求用户操作节点；不要把全部问题堆成几十项问卷；不要因阶段齐全就自动进入生成。
