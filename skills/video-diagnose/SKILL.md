# 视频局部修复

读 [项目约定](references/project-contract.md)、[LibTV 规则](references/libtv.md) 与 [质量规则](references/quality.md)。只处理用户指出的问题和必要依赖，不默认重开整片。

## 执行

1. 读三文件、当前工程、原批准产物和实际问题段。把“怪/不自然”收敛为时间码、可看到/听到的现象、期望保留内容。
2. 建立最小复查方法：同一时间段完整播放/音轨对照/相邻镜头对照/字段回读。没有实际素材时只能列待验证假设；不称已定位。
3. 先排查素材错配、提示词过载、动作不清、终态缺失、机位逻辑、连续性、能力不匹配。复杂问题列 3–5 个可反证假设，再一次只改变一个变量；明显拼写错误直接修，不强加假设表。
4. 实际修改LibTV工程时读取项目级 edges 与时间线得到影响范围；只有本地视频/音轨时，从源文件、编辑指令和前后内容确定影响范围，不要求额外平台连接。列 `目标节点/必要下游/相邻检查/应保持不变的节点和媒体`。只读 read_node 不足以证明依赖。
5. 提出最小改动。旁白改词只修音频/字幕/必要剪辑；可见说话段再查口型。构图问题修参考；节奏问题改时间线，不重生成全部画面。
6. 修改前保存旧产物稳定引用或备份及目标字段。画布非生成修改经原授权可继续；任何生成重做经 Implement 同一预算/幂等/版本规则，已有批准的额度内不重复要许可。
7. 修改后回读目标与无关节点；生成后完整播放问题段、相邻切点，并对照人物/产品/场景不变项。技术问题看数据，动作/口型问题必须视听。
8. 通过才更新 selected 引用与必要下游合成，保留 previous_outputs；不通过留候选与诊断证据。记录旧/新对比与最小修复结论。

## 验收例

用户“第二段台词改为周末见”：先确认是画外音还是人物口播；读取实际音轨/字幕；精确替换该句；复听新句、重排字幕和必要时长；人物可见时检查局部口型；对照第一/三段原媒体引用与实际内容。
不能靠“第一段节点没变”就证明最终合成第一段没变：还要检查时间线引用、裁切点与输出画面。

## 失败分支

| 触发 | 第一处理 | 仍失败 |
| --- | --- | --- |
| 本地无任务但节点在运行 | 恢复节点 taskId，记录 submitted/running | unknown 时停止重新生成 |
| 同 diagnosis 第二次失败 | 用现有证据检查上游假设 | 不追加同参数第三次 |
| 修复改变无关内容 | 保留失败候选，恢复原 selected 引用 | 不销毁批准版本；说明回退是否实测 |
| 平台只能整段重拍 | 检查该段实际约束与局部替代方案 | 报告范围和费用，不能谎称局部修好 |

## 禁止

不要直接把所有问题归因模型；不要改 SPEC 让坏输出看似合规；不要改完提示词就称画面已修；不要因接口冲突覆盖他人改动。
不要从空时间线通过推断真实剪辑通过；不要用旧 graphRevision 充当 expectedRevision。

## 已授权的局部修订

用户明确的局部改词按项目约定“批准继承”执行：更新受影响文件的哈希并追加revision_evidence，保留未改素材批准、原预算上限和全部消费/尝试记录。只有超出原授权范围才请求新增批准；不得仅因文件哈希变化重复询问同一修改。
